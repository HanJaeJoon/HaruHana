# HaruHana 설계 결정 기록

설계 세션(2026-08)에서 미해결 쟁점 7개를 하나씩 해소하며 결정을 누적한 기록. 스펙 문서(`haruhana-spec.md`)의 원천 자료.

근거로 삼은 "사용자 노트"는 The One Thing(2023년 독서) 정리 노트로, HaruHana 아이디어의 원형이 담겨 있다. 개인 노트라 이 저장소에는 포함하지 않으며, 필요하면 `../jj-note` 저장소에서 찾을 것 (`_old/2023/2_Reading/1_The_One_Thing.md`).

## 결정 1. streak 대신 "66일 여정" (쟁점 1 해소, 2026-08-19)

**연속(consecutive) 개념을 버리고 축적(cumulative)으로 대체한다.**

- 지표는 **누적 달성 일수 / 66일** ("습관 형성까지 41/66일"). 놓친 날은 전진이 없을 뿐, 쌓은 것이 무너지지 않는다 (0 리셋 없음)
- 66일 도달 시 "습관 형성" 마일스톤 축하. 이후에는 누적 총 일수 + 월 밀도("이번 달 18/22")로 전환
- 보조 지표로 월 밀도를 항상 병기 - 순수 누적의 약점(장기간에 걸쳐 66일을 채우는 경우)을 밀도가 드러낸다. v1에서는 이동 윈도우 같은 복잡한 규칙은 넣지 않는다
- 달력 뷰는 **해낸 날만 표시**하는 "성공 목록" 형태. 끊긴 지점을 시각적으로 강조하지 않는다
- 기존 확정 설계(핵심 구조) 스케치의 "연속 12일" 표기는 "누적 N/66일"로 교체

**근거 (사용자 노트 기반):**

- 노트의 "줄 긋기 게임" 실패 모드는 (1) 폭의 게임(모든 할 일 나열)과 (2) 완결성 게임("하나씩 놓치지 않고"). (1)은 하루 하나 제약이 구조적으로 차단하지만, 고전 streak는 (2)를 그대로 재현한다 - 거짓 체크 유인, 기준 하향 유인, 끊김 후 이탈
- 책의 일관성은 무한 사슬이 아니라 "66일이라는 종점이 있는 단거리 경주" ("성공은 단거리 경주다")
- "성공 목록" 원칙을 기록 표시에 적용: 기록은 해낸 날의 축적으로 읽혀야지 끊긴 지점의 강조로 읽히면 안 된다
- (외부 보조 근거) 66일의 출처인 Lally 연구(2010)는 하루 놓침이 습관 형성에 유의미한 영향을 주지 않는다고 보고 - 0 리셋은 책이 인용한 연구와도 어긋남

**파생 효과:** "끊기면 0"이 없으므로 거짓 체크 유인이 사라져 쟁점 5(과거 기록 수정 허용)의 정직성 문제가 가벼워진다.

## 결정 2. 정량 기준은 문구에 포함, 판정은 이진 체크 (쟁점 2 해소, 2026-08-19)

**"오늘의 하나"는 자유 텍스트 하나. 정량 기준은 그 문구 안에 들어가고, 앱은 아무것도 측정하지 않는다.**

- 예: "최소 1시간 책 읽기", "1장 분량 오토마토 3개"
- 판정 주체는 사용자. 앱은 [해냈다]/[못 했다]만 받는다
- 온보딩에서 "정량적 최소 기준을 문구에 넣으세요"라고 안내
- 구조화된 정량 필드(단위/수치), 달성량 입력, 타이머는 넣지 않는다

**근거 (사용자 노트 기반):**

- 노트 원형이 정확히 이 구조: "하루에 최소 1시간 읽기를 **실천하면 체크**" - 기준은 존재하되 판정은 사용자 스스로
- 책의 "성공은 철저한 자기관리에서 온다" - 자기관리를 앱이 대행하지 않는다
- 달성량 입력은 매일의 마찰 + "수치 채우기"라는 새 게임화 (결정 1과 방향 충돌)
- 타이머는 범위 폭증(foreground service 등) + 집중 중 폰 사용 유도 (책의 메시지와 충돌)
- 이 앱의 지표는 "며칠 해냈나"이지 "몇 시간 했나"가 아님

## 결정 3. 계단은 2층만 저장, 온보딩의 사고 도구로 활용 (쟁점 3 해소, 2026-08-19)

**저장/추적하는 층은 올해 목표 + 오늘의 하나, 2층뿐이다. 책의 6층 계단은 온보딩에서 목표를 세울 때의 안내 흐름으로만 쓴다.**

- 목표 설정 화면에서 "최종적으로 무엇을 이루고 싶은가 -> 그렇다면 올해는?" 식으로 거슬러 내려오는 안내 문구를 보여주되, 저장하는 것은 올해 목표 하나뿐
- 월/주 목표는 저장하지 않는다

**근거 (사용자 노트 기반):**

- 노트의 앱 아이디어 자체가 2층: "올해 목표를 하나 정해서... 하루에 최소 1시간"
- 책의 계단("최종 -> 5년 -> 올해 -> 이번달 -> 이번주 -> 지금 당장 단 하나")은 목표를 세울 때 거슬러 내려오는 사고 도구이지, 6개 층을 각각 추적하라는 뜻이 아님 (노트의 맥락: "우선순위에 따라 살아라")
- 층이 늘면 관리 목록이 늘어 줄 긋기 게임으로 회귀 + "하나만" 차별점 희석
- 쟁점 7(초점탐색 질문의 온보딩 활용)과 자연스럽게 연결됨

## 결정 4. 목표는 자유 완료/교체, 이력은 아카이브로 보존 (쟁점 4 해소, 2026-08-19)

- 목표에 [달성했다] 액션: 축하 -> 목표와 기간 전체 기록을 읽기 전용 아카이브로 이동 -> 새 목표 설정 흐름
- 중간 교체도 같은 경로 (달성이 아닌 "마감"으로 구분만 남김). 교체 전 확인 단계 한 번으로 마찰만 부여, 횟수 제한 없음
- **66일 여정은 목표 단위로 시작한다.** 목표 교체 = 새 습관 = 새 카운트. 같은 목표 안에서 "오늘의 하나" 문구만 수정하면 카운트 유지
- 아카이브 화면 = 지난 성공 목록 (목표, 기간, 달성 일수)

**근거 (사용자 노트 기반):**

- "올해 목표"는 자연 종점이 있으므로 완료 경로가 필수
- 책의 "정답을 고르기보다 방향을 정해라" - 목표는 수정될 수 있다. 교체를 막는 것이 오히려 책과 어긋남
- "성공 목록" 원칙 - 끝난 목표와 달성 기록이야말로 성공 목록. 이력 삭제는 원칙 위배
- 66일 = 습관 형성 시간이고 습관 = 오늘의 하나이므로, 오늘의 하나가 바뀌는 목표 교체 시 카운트가 새로 시작하는 것이 논리적

## 결정 5. 소급 기록은 어제까지만 (쟁점 5 해소, 2026-08-20)

- 기록/수정 가능 범위는 **오늘 + 어제**. 그 이전 날짜는 잠김 (달력에서 과거 날짜 탭 불가)
- 어제가 미기록이면 앱 진입 시 오늘 카드 위에 "어제는 어땠나요?" 프롬프트로 자연스럽게 회수
- [해냈다]/[못 했다] 간 전환도 같은 범위에서만 허용

**근거:**

- 결정 1(리셋 없음)로 소급 체크의 거짓 유인이 이미 제거됨 - 지킬 사슬이 없다
- 결정 2(판정 주체는 사용자)와 일관: 오늘의 자기 보고를 믿으면서 어제만 의심할 이유가 없다
- 남는 문제는 정직성이 아니라 기록 정확성: 가장 흔한 실수(실천했는데 체크를 잊고 잠듦)를 막으면 해낸 날이 기록에서 빠지는 역설
- 무제한 소급은 "달력 채우기 게임"(줄 긋기 게임의 변형)이 되고, 며칠 지난 실천 기억은 흐려 정확성에도 도움이 안 됨

## 결정 6. 광고는 전 화면 하단 공통 배너 1개 (쟁점 6 해소, 2026-08-20)

- expo-router 루트 레이아웃에 kit `AdBanner` 1개 배치, 모든 화면(오늘/달력/아카이브/설정) 하단 공통 노출
- 전면 광고(interstitial)는 넣지 않는다 - 매일 여는 앱에서 핵심 순간(체크 직후) 침범은 이탈 직결, kit에 모듈도 없음

**근거:**

- 회당 수십 초, 거의 메인 화면만 보는 사용 패턴이라 메인 무광고 = 사실상 무광고 앱 (수익형 앱 전제와 충돌)
- 하단 고정은 표준 UX, 체크 버튼(화면 중앙)과 거리 확보로 오클릭 유도 없음 (AdMob 정책 안전)
- 배치 지점 1곳으로 구현 최소

## 결정 7. 7개 영역은 목표의 선택적 태그 + 온보딩 영감 도구 (쟁점 7 해소, 2026-08-20)

- 목표 설정 시 7개 영역(정신적 행복, 신체적 건강, 개인적 삶, 핵심 인간관계, 일, 회사, 재정적 문제)을 선택지로 제시. 건너뛰기 가능, 저장은 목표에 붙는 태그 1개뿐
- 목표는 여전히 전체에서 1개 - 영역별 목표는 허용하지 않는다
- 초점탐색 질문은 "오늘의 하나" 설정 단계의 안내 문구로 사용: "그 목표를 위해, 다른 모든 일들을 쉽게 혹은 필요 없게 만들 단 하나의 일은 무엇인가요?"
- 아카이브에 영역 태그가 쌓이면 지난 목표들의 영역 분포가 보임 (책의 "일과 삶의 균형")

**근거:**

- 책은 영역마다 하나씩을 묻지만, 곧이곧대로 구현하면 목표 7개 = 카테고리 있는 습관 트래커 = "하나만" 차별점 파괴
- 결정 3의 원칙 재적용: 책의 구조물은 저장 대상이 아니라 온보딩의 사고 도구

# 2차: 구현 전 잔여 항목 확정 (2026-08-20)

스펙 초안 11절에 "구현 전 확인 필요"로 남겨둔 항목들을 해소한 기록.

## 결정 8. 완전 무채색 디자인 (스펙 11절 잔여 항목 외, 세션 중 추가 결정)

**색을 쓰지 않는다. 흑백과 회색 계조만으로 전부 표현한다.**

- 원서 표지처럼 무채색 기조, 노션 아이콘 계열의 절제된 도형. 앱 아이콘/스플래시/스토어 그래픽까지 동일 방침
- kit `brandColor`를 유채색 1개로 두는 대신 **테마별 accent로 반전**: 라이트에서 accent `#111111` + 흰 글씨, 다크에서 accent `#f2f2f2` + 검정 글씨. 단일 상수를 검정으로 두면 다크 모드에서 버튼이 배경(`#121212`)에 묻힌다
- 상태 구분은 색 대신 **채움/외곽선/굵기**로: [해냈다]는 채운 버튼, [못 했다]는 외곽선 버튼
- 달력 마킹도 무채색 채움 점 하나 (결정 1의 "해낸 날만 표시" 원칙 유지)
- `bannerBg` override도 무채색으로 (라이트 `#eeeeee` / 다크 `#262626`). 광고 크리에이티브 자체의 색은 통제할 수 없으므로, 배너 위에 경계선과 여백을 두어 본문과 시각적으로 격리한다

**근거:**

- "하루에 하나만"이라는 제약이 유일한 차별점인 앱에서, 색까지 절제하는 것이 메시지와 일관된다. 색으로 유도하는 것 자체가 게임화의 재료(결정 1이 배제한 방향)
- kit 기본 팔레트(`src/kit/theme.ts`)가 이미 완전 무채색이다. 유채색은 앱이 넘기는 `brandColor`와 `bannerBg` 두 곳뿐이므로, 무채색 방침은 kit을 거스르는 게 아니라 kit 기본값을 그대로 쓰는 쪽에 가깝다 (구현 비용이 오히려 낮다)
- 이 앱은 kit `chart`/`share`를 쓰지 않으므로 `brandColor`의 사용처가 버튼뿐이다. 테마별 반전의 영향 범위가 좁다
- 마이크로앱 포트폴리오 안에서의 식별성도 확보된다 (loan-calculator는 `#1F6F54` 녹색)

## 결정 9. 알림 시각은 기본값 없이 온보딩에서 선택 강제

- 온보딩 알림 단계에서 **프리셋 07:00 / 08:00 / 09:00 / 직접 입력 / 알림 없이 쓰기** 중 하나를 고르기 전에는 다음으로 넘어갈 수 없다 (미리 선택된 값 없음)
- "알림 없이 쓰기"를 반드시 선택지로 둔다 - 선택 강제가 막다른 길이 되지 않게
- 데이터 모델 변경 없음: `settings.notificationTime`이 `'HH:mm'` 또는 `null`(꺼짐)

**근거:**

- 노트 근거("의지력이 떨어지기 전에 가장 중요한 한 가지 일에 집중해라")는 "아침"이라는 방향까지만 뒷받침한다. 08:00 같은 특정 시각은 근거가 없는 임의값이었다
- 08:00은 통근/통학 이동 시간과 겹칠 수 있어, 알림을 보고도 체크 액션으로 이어지지 않는다. 기상 시각은 사람마다 다르므로 앱이 정할 문제가 아니다
- 결정 2의 "판정 주체는 사용자" 원칙의 연장: 자기 리듬을 스스로 정하게 한다. 온보딩 단계가 한 화면 늘지 않고(이미 5단계에 알림 시각이 있음) 프리셋 선택이라 마찰도 작다

## 결정 10. 아카이브 상세는 v1 생략, 단 확장 가능하게 설계

- 아카이브는 카드 요약(제목, 영역 태그, 기간, 누적 달성 일수, 달성/마감 구분)까지만. 카드 탭으로 들어가는 지난 목표 달력은 v1에서 만들지 않는다
- 대신 달력을 **`records` 배열을 prop으로 받는 순수 컴포넌트**로 설계한다 (활성 목표의 기록을 내부에서 직접 읽지 않는다). v2에서 아카이브 항목의 records를 그대로 넘기면 상세 화면이 붙는다

**근거:**

- 아카이브의 목적(결정 4)은 "지난 성공 목록"이고, 카드 요약만으로 그 목적은 충족된다
- 데이터는 아카이브에 이미 records까지 저장하므로 v1에서 빼도 영구적 손실이 없다 (나중에 켜면 과거 기록이 그대로 보인다)
- 순수 컴포넌트 제약은 그 자체로 좋은 설계이고 테스트도 쉬워, 확장 여지를 남기는 비용이 사실상 0이다

## 결정 11. "이미 기록한 날 알림 스킵"은 v1 미지원 (항상 발송)

- `expo-notifications`의 매일 반복 트리거 1개로 끝낸다. 그날 이미 체크했더라도 알림은 발송된다

**근거:**

- 반복 트리거는 조건부 발송을 지원하지 않는다. 구현하려면 "다음 1회" 알림을 앱 진입/체크마다 재스케줄하는 구조가 되는데, 사용자가 며칠 앱을 열지 않으면 알림 자체가 끊긴다. 리마인더가 가장 필요한 상황에서 리마인더가 사라지는 셈이라 트레이드오프가 명확히 나쁘다
- 이미 체크한 날의 알림은 경미한 재잔소리에 그친다. 신뢰성(절대 누락되지 않음)을 우선한다
