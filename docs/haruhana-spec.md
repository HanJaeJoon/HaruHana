# HaruHana 스펙 초안

작성: 2026-08-20. 근거: The One Thing 독서 노트(2023, 개인 노트라 저장소 미포함 - 필요하면 `../jj-note` 저장소의 `_old/2023/2_Reading/1_The_One_Thing.md` 참고)와 `design-decisions.md`(쟁점 7개 해소 기록), 설계 세션의 확정 설계 2건(핵심 구조, 로컬 알림 방침).

## 1. 개요

**올해 목표 1개와, 그 목표를 전진시키는 "오늘의 하나" 1개만 허용하는 일일 체크 앱.**

- 유일한 차별점: "하나만 허용한다"는 제약 자체 (일반 습관 트래커는 습관을 10-20개로 늘리게 유도)
- 원형: 사용자의 책 노트 - "올해 목표를 하나 정해서(나의 예시는 책읽기) 하루에 최소 1시간 읽기를 실천하면 체크할 수 있는 서비스"
- 100% 오프라인, 서버 없음, 운영비 0원. 수익은 하단 배너 광고

### 설계 원칙 (노트에서 도출된 제약)

1. **체크리스트 게임 금지** - 줄 긋기의 쾌감이 아니라 목표의 전진이 동기여야 한다. 연속(streak) 개념 없음, 끊김을 강조하는 표시 없음
2. **판정 주체는 사용자** - 앱은 측정/검증하지 않는다. 자기관리를 대행하지 않는다
3. **책의 구조물(계단, 7영역, 초점탐색 질문)은 저장 대상이 아니라 온보딩의 사고 도구**
4. **기록은 성공 목록으로 읽혀야 한다** - 해낸 날의 축적을 보여주고, 못 한 날을 강조하지 않는다

## 2. 핵심 개념과 규칙

### 목표 (Goal)

- 전체에서 **활성 목표는 항상 1개** (온보딩 전에는 0개)
- 필드: 제목(자유 텍스트), 영역 태그(7개 중 1개, 선택), 생성일
- [달성했다] 또는 [마감] 액션으로 종료 -> 기록과 함께 아카이브로 이동 (읽기 전용) -> 새 목표 설정 흐름
- 교체 횟수 제한 없음, 교체 전 확인 단계 1회

### 오늘의 하나 (One Thing)

- 목표에 딸린 **자유 텍스트 1개**, 매일 같은 것 (매일 새로 정하지 않음)
- 정량적 최소 기준은 문구 안에 포함 (예: "최소 1시간 책 읽기"). 앱은 측정하지 않음
- 같은 목표 안에서 문구 수정 가능 (66일 카운트 유지)

### 일일 기록 (Daily Record)

- 하루당 [해냈다] / [못 했다] / 미기록 3상태
- 기록/수정 가능 범위: **오늘 + 어제만**. 그 이전은 잠김
- 어제 미기록이면 앱 진입 시 "어제는 어땠나요?" 프롬프트

### 66일 여정 (streak 대체)

- 지표는 **누적 달성 일수 / 66** (연속 아님, 0 리셋 없음). 놓친 날은 전진이 없을 뿐
- 66일 도달 시 "습관 형성" 축하 (1회). 이후 누적 총 일수 + 월 밀도로 전환
- 보조 지표: 월 밀도 "이번 달 18/22" (분모 = 이번 달 오늘까지의 일수)
- 카운트는 목표 단위. 목표 교체 = 새 습관 = 새 카운트

## 3. 화면 구성 (expo-router)

```
루트 레이아웃: 하단 AdBanner 1개 (전 화면 공통)
  /            오늘 (메인)
  /calendar    기록 달력
  /archive     지난 목표 (성공 목록)
  /settings    설정
  온보딩: 활성 목표가 없으면 목표 설정 흐름으로 (첫 실행 포함)
```

### 3.1 오늘 (메인)

```
[ 목표 ]  상반기 기준 토익 달성
   |
[ 오늘의 하나 ]
   "1장 분량 오토마토 3개"
   [ 해냈다 ]   [ 못 했다 ]

습관 형성까지  #########-------  41/66일
이번 달 18/22
```

- 어제 미기록 시 오늘 카드 위에 어제 회수 프롬프트
- 체크 후에는 상태 표시 + 되돌리기 가능 (오늘/어제 범위 내 전환 허용)
- 66일 도달일에 축하 표시. 66일 이후에는 진행 바 대신 "누적 N일" 표기

### 3.2 기록 달력

- 월 단위 달력, **해낸 날만 마킹** (못 한 날/미기록은 빈 칸과 동일한 시각 무게 - 끊김 강조 금지)
- 오늘/어제만 탭 가능, 과거는 읽기 전용
- 월 이동으로 현재 목표 기간의 과거 조회

### 3.3 아카이브 (지난 성공 목록)

- 지난 목표 카드 목록: 제목, 영역 태그, 기간, 누적 달성 일수, 달성/마감 구분
- 항목 탭 시 그 목표의 달력 읽기 전용 조회 (v1에서는 생략 가능 - 카드 요약만으로 시작해도 됨)

### 3.4 설정

- 알림 시각 변경 / 알림 끄기
- 오늘의 하나 문구 수정, 목표 [달성했다]/[마감] 진입점
- 언어는 시스템 로케일 따름 (ko/en)

## 4. 온보딩 흐름 (목표 설정 흐름과 동일, 재사용)

1. **계단 안내** - "최종적으로 무엇을 이루고 싶은가 -> 그렇다면 올해는?" 거슬러 내려오는 안내 문구 (저장 없음)
2. **영역 선택 (선택 사항)** - 7개 영역 제시, 건너뛰기 가능. 목표가 막막한 사용자의 영감 재료
3. **올해 목표 입력** - 자유 텍스트. "크고 구체적으로" 안내 문구
4. **오늘의 하나 입력** - 초점탐색 질문을 안내 문구로: "그 목표를 위해, 다른 모든 일들을 쉽게 혹은 필요 없게 만들 단 하나의 일은 무엇인가요?" + "정량적 최소 기준을 문구에 넣으세요" (예시 제시)
5. **알림 시각** - 기본 아침 (가안 08:00, 근거: "의지력이 떨어지기 전에 가장 중요한 한 가지 일에 집중해라"). 변경/끄기 가능

## 5. 데이터 모델 (kit `createPrefs` 위에서)

`kit/prefs.ts`는 키당 단일 JSON 값을 저장하므로 **키를 4개로 분리**한다:

```ts
// haruhana.goal - 활성 목표 (없으면 null)
{ id: string, title: string, area?: Area, oneThing: string, createdAt: string /* YYYY-MM-DD */ }

// haruhana.records - 활성 목표의 일별 기록 배열 (연간 최대 ~365개, 단일 JSON으로 충분)
Array<{ date: string /* YYYY-MM-DD, 로컬 기준 */, done: boolean }>
// 미기록은 항목 없음으로 표현. 누적 달성 일수 = done=true 개수 (파생값, 저장하지 않음)

// haruhana.archive - 지난 목표 배열 (기록 포함, 읽기 전용)
Array<{ goal: Goal, records: Record[], closedAt: string, outcome: 'achieved' | 'closed' }>

// haruhana.settings
{ notificationTime: string | null /* 'HH:mm', null = 꺼짐 */, celebrated66: boolean }
```

- 파생값(누적 일수, 월 밀도, 66 도달 여부)은 records에서 계산 - 저장 안 함 (불일치 원천 차단). 예외: 축하 1회 노출 플래그(`celebrated66`)만 저장
- 날짜는 기기 로컬 기준 `YYYY-MM-DD` 문자열. 시간대 이동으로 생기는 극단 케이스는 v1에서 다루지 않음
- 각 키에 `isValid` 가드 필수 (kit 계약)

## 6. 로컬 알림 (앱 코드로 구현, kit 승격 보류)

- `expo-notifications`, 매일 반복 로컬 알림, 서버 불필요
- 문구에 오늘의 하나 포함: "오늘의 하나: {문구}" - 문구/시각 변경 시 재스케줄
- 기본 시각 아침 (가안 08:00), 설정에서 변경/끄기
- **kit에 넣지 않는다** - "사용처 1개면 승격하지 않음" 원칙. 두 번째 알림 사용 앱이 나올 때 승격 (설계 세션 확정 사항)
- 이미 오늘 기록이 있으면 그날 알림 스킵 여부: v1에서는 단순화를 위해 항상 발송 (반복 알림 API 특성상 조건부 발송은 복잡도 증가) - 구현 시 재검토

## 7. 광고

- kit `AdBanner` 1개, 루트 레이아웃 하단 고정, 전 화면 공통
- 전면 광고 없음
- 체크 버튼은 화면 중앙 배치로 배너와 거리 확보 (오클릭 유도 금지, AdMob 정책)

## 8. 기술 스택 (kit/microapp-starter와 동일)

- Expo SDK 54, TypeScript strict, Jest 29 (jest-expo), ESLint 9 flat config
- `react-native-google-mobile-ads` 16.3.4 고정
- kit 모듈 사용: `theme`, `prefs`, `i18n`, `ads/AdBanner`. (currency/chart/share는 이 앱에서 불필요 - 단 66일 진행이나 월 밀도 추이에 chart를 쓸 가능성은 v2 여지로)
- 빌드: GitHub Actions (`expo prebuild` + Gradle `bundleRelease`)
- i18n: ko/en, `createI18n` + `pickSupportedLocale`

## 9. 엣지 케이스

- **자정 경계**: "오늘"은 기기 로컬 날짜. 앱을 켜둔 채 자정을 넘기면 포그라운드 복귀 시 날짜 재평가
- **어제 프롬프트와 목표 교체가 겹칠 때**: 목표 교체 시 이전 목표의 미기록 어제는 그대로 미기록으로 아카이브 (소급 입력 흐름 생략 - 단순화)
- **66일 축하 중복**: `celebrated66` 플래그로 1회만. 목표 교체 시 플래그 리셋
- **활성 목표 없음**: 모든 탭에서 온보딩(목표 설정 흐름)으로 유도
- **과거 기록 수정으로 66 미만 회귀**: 어제 체크 취소로 66 -> 65가 될 수 있음. 축하는 이미 노출됐어도 되돌리지 않음 (플래그 유지)

## 10. 구현 계획 (microapp-starter 완료 후 착수)

선행: microapp-starter 저장소 생성(Phase 3), 대출 상환 계산기로 kit 검증(Phase 4).

1. starter 복제 -> HaruHana 저장소에 새 커밋으로 내용 교체 (기존 .NET 코드는 이력에 보존하고 새 커밋으로 교체하기로 확정)
2. 저장소 Public -> Private 전환
3. 데이터 계층: prefs 4키 + isValid + 파생값 계산 함수 (순수 함수, 단위 테스트 우선)
4. 오늘 화면 (체크, 어제 프롬프트, 66일 진행 바, 월 밀도)
5. 온보딩/목표 설정 흐름
6. 달력, 아카이브, 설정 화면
7. 로컬 알림
8. 출시 반복 작업 (앱마다 반복되는 체크리스트: 키스토어, Secrets 4개, `EXPECTED_UPLOAD_CERT_SHA256`, AdMob 앱/배너 단위, Play 등록정보 웹사이트 `https://hanjaejoon.github.io`, 콘텐츠 선언, IARC, 출시 후 `git tag vc<N>`)

## 11. 가정 (구현 전 확인 필요 항목)

- 알림 기본 시각 08:00은 가안 (아침이라는 방향만 노트 근거로 확정)
- 아카이브 상세(지난 목표의 달력 조회)는 v1 생략 가능으로 표시
- "이미 기록한 날 알림 스킵"은 v1 미지원 가안
- 앱 이름/스토어 문구, 아이콘 등 스토어 자산은 미설계
