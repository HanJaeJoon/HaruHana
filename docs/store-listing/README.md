# Play Store 등록정보

앱 내 다국어(i18n)는 코드에 포함되어 자동 적용되지만, 스토어 등록정보는 Play Console
에서 언어별로 직접 붙여넣어야 한다.

HaruHana 가 지원하는 언어는 `ko` / `en` 두 개다(`src/lib/i18n/translations.ts`).
스토어 등록정보도 같은 두 개만 만든다. 앱이 지원하지 않는 언어로 등록정보만 늘리면
설치한 사용자가 읽을 수 없는 화면을 만나게 된다.

## 등록 절차

1. Play Console > HaruHana > 스토어 설정 > **기본 스토어 등록정보**
2. 기본 언어(한국어)에 `ko-KR.md` 내용을 붙여넣기
3. 우측 상단 **번역 관리** > "직접 번역 추가" > 영어(미국) en-US
4. `en-US.md` 내용을 붙여넣기

## 입력 진행 상황과 검증용 글자 수

Play Console 은 각 입력란 아래에 글자 수를 실시간으로 보여준다. **붙여넣은 뒤 이
표의 숫자와 같은지 확인하면 잘려 들어가거나 깨진 것을 바로 잡을 수 있다.**

| 파일 | 앱 이름 | 간단한 설명 | 자세한 설명 | 자세한 설명 SHA-256 앞 8자 | 상태 |
|---|---|---|---|---|---|
| `ko-KR` | 4 | 43 | 1214 | `0a252477` | 초안 (미입력) |
| `en-US` | 8 | 70 | 2247 | `4aae25eb` | 초안 (미입력) |

해시는 `## ` 헤딩으로 자른 각 구획을 `strip()` 한 문자열의 SHA-256 이다.
문구를 고치면 이 표도 다시 뽑아 갱신할 것:

```bash
python - <<'EOF2'
import io, re, hashlib
for loc in ["ko-KR","en-US"]:
    s = io.open("docs/store-listing/%s.md" % loc, encoding="utf-8").read().replace(chr(13), "")
    parts = [p.strip() for p in re.split(r'^## .*$', s, flags=re.M)[1:]]
    print(loc, " ".join("%d/%s" % (len(v), hashlib.sha256(v.encode()).hexdigest()[:8]) for v in parts))
EOF2
```

**자동 입력을 쓸 때는 반드시 글자 수나 해시로 대조할 것.** loan-calculator 에서
키 입력을 하나씩 흘려 넣다가 IME 조합이 뭉개져 한글이 깨진 적이 있다(`비교` ->
`바교`). 클립보드에 넣고 Ctrl+V 로 붙여넣으면 IME 를 거치지 않는다. 그때 쓴 명령:

```bash
powershell.exe -sta -NoProfile -Command \
  "Set-Clipboard -Value ([IO.File]::ReadAllText('C:\path\to\text.txt', [Text.Encoding]::UTF8))"
```

`clip.exe` 는 쓰지 않는다(UTF-16LE BOM 을 문자로 남긴다). PowerShell 은 `-sta`
로 띄워야 실제 데스크톱 클립보드에 닿는다.

## 글자 수 제한

| 항목 | 제한 |
|---|---|
| 앱 이름 | 30자 |
| 간단한 설명 | 80자 |
| 자세한 설명 | 4,000자 |

## 앱 이름에 대해

한국어 등록정보의 앱 이름을 `하루하나` 4자로 두었다. 런처에 뜨는 이름
(`app.json` 의 `expo.name`)은 `HaruHana` 라 서로 다르다. 한글 검색 노출을 위해
한국어 등록정보만 한글 이름을 쓴 것이다.

검색 노출이 부족하면 `하루하나 - 오늘의 하나`(13자)처럼 짧은 부제를 붙일 수 있다.
키워드를 나열하는 이름은 Play 정책 위반이므로 하지 않는다.

## 문구를 쓸 때 지킨 것

**차별점을 앞세운다.** 습관 앱은 이미 많다. 그래서 "하나만 허용한다", "연속 일수를
세지 않는다", "색을 쓰지 않는다", "앱이 판정하지 않는다" 네 가지를 설명의 축으로
삼았다. 전부 스펙 1절의 설계 원칙 그대로이고, 경쟁 앱이 반대로 하는 지점이다.

**66일을 효과 주장으로 쓰지 않는다.** "자주 인용되는 숫자"이고 앱은 이것을 "목표가
아니라 눈금으로 쓴다"고 적었다. 습관 형성 기간에는 개인차가 크고, 근거 없는 효능
주장은 Play 정책 위반이다. 건강/심리 개선을 약속하는 표현도 넣지 않았다.

**책 이름을 쓰지 않는다.** 이 앱의 발상은 개인 독서 노트에서 왔지만, 등록정보에
책 제목을 넣으면 제휴/공식 앱으로 오해될 수 있다.

**광고 형태를 미리 밝힌다.** "하단 배너 하나, 전면 광고 없음"을 적었다. 광고 있는
무료 앱에서 리뷰 평점을 깎는 가장 큰 원인이 예상 못 한 전면 광고다.

**과장하지 않는다.** "최고", "1위" 같은 표현을 쓰지 않았다. Play 정책이 근거 없는
우위 주장을 금지한다.

## 스크린샷 (미완 - 실기기에서 찍어야 함)

내부 테스트로 앱을 깐 뒤 아래 4장을 찍으면 충분하다. **기록이 어느 정도 쌓인 상태로
찍어야 의미가 산다.** 갓 설치한 상태는 전부 빈 화면이다.

1. 오늘 화면 (목표 + 오늘의 하나 + 두 버튼 + 66일 진행 바)
2. 달력 (해낸 날 점이 흩어져 있는 상태)
3. 온보딩의 목표 입력 단계 ("하나만 정한다"가 드러나는 화면)
4. 아카이브 또는 설정

- Play 요구: 최소 2장, 16:9 또는 9:16, 짧은 변 최소 320px, 긴 변 최대 3840px
- 언어별로 따로 올릴 수 있다. 안 올리면 기본 언어 스크린샷이 모든 언어에 쓰인다
- 찍은 파일은 `docs/store-listing/screenshots/` 에 넣어 두면 다음 업데이트 때
  재사용할 수 있다

무채색 방침 때문에 스크린샷이 밋밋해 보일 수 있다. **그래도 색을 입힌 홍보 이미지를
만들지 않는다.** 등록정보의 첫인상과 실제 앱이 어긋나는 편이 더 나쁘다.

## 그 밖에 Play Console 이 요구하는 것

| 항목 | 규격 | 상태 |
|---|---|---|
| 앱 아이콘 | 512x512 PNG | **미완** - `scripts/make-icons.py` 에 512 출력 추가 필요 |
| 그래픽 이미지 | 1024x500 PNG/JPG | **미완** |
| 스크린샷 | 최소 2장 | **미완** - 실기기에서 촬영 |
| 개인정보처리방침 URL | 공개 URL | **미완** - `docs/privacy-policy.md` 원본은 작성됨 |

개인정보처리방침은 `HanJaeJoon/HanJaeJoon.github.io` 저장소에
`haruhana-privacy/index.html` 로 올린다. URL 은
**https://hanjaejoon.github.io/haruhana-privacy/** (끝 슬래시 필요).

**스토어 등록정보의 웹사이트 필드는 `https://hanjaejoon.github.io` 다.**
AdMob 이 앱별 등록정보의 도메인을 크롤링해 앱을 인증하고, app-ads.txt 가 그 도메인
루트에 있어야 하기 때문이다. 개인정보처리방침 URL 과는 별개 항목이다.
